## 0. 一句话

人和 agent 用一整块时间把方向谈透，签一份契约；之后 agent 无人值守地探索，**一次运行只交给人一样东西**——一篇能从头读到尾的草稿（或一页空结果报告）。运行期间不打扰人。运行的全部状态在文件里、经 CLI 写入，**任何一家 agent CLI 打开这个目录都能接手**。

要解决的不是「agent 跑不久」，而是 v2 §0 的同一个约束在无人值守时的形态：新名词多、信息碎、人要反复加载工作记忆。所以本设计里几乎每个决定都在回答同一个问题：**这件东西到人面前时，要花他多少工作记忆。**

## 1. 本文新引入的词（只有这十个）

| 词 | 意思 |
|---|---|
| 运行 | 一次无人值守的探索，从签契约到交报告。`threads/` 里一篇 `kind: run` 的 note |
| 契约 | 运行 note 的正文：动机、方向、不在乎清单、停止条件、口味。agent 写，人签；**签了就冻结** |

| 熟悉度账本 | 人对每个概念的态度：会 / 要讲义 / 已有讲义。用户级，跨项目 |

## 2. 对 design-v2 的修改（只有这五处）

1. **§7「无人在场只执行确定性项」** → 改为：无人在场时，只有**一份人签过字的契约**能授权要 LLM 的项；没有在跑的运行时，原句不变。`next` 仍然只提议、不做事。
2. **§4 对象模型** → 加 `kind: run`（§3）；命题加可选字段 `premises: [[命题]]`（§6）。`depends_on` 含义不变，仍只指概念。
3. **§6「只有三类事件叫人」** → 运行期间这三类事件**一律停放**，运行结束后只有落在某篇报告依赖链上的才到人面前（§7）。
4. **§10 强制输出** → 运行中开出的命题**不问押注，事后也不补问**（事后的预测不是预测，v2 §4 已有此判断）。人的押注挪到签约时，押在方向上（§3）。`coaching: strict` 的「无预测不推导」在运行内不生效。
5. **§8 skill 清单** → 加三个（共 12 个）：`discuss`（讨论阶段）、`mentor`（运行阶段）、`brief`（写运行报告和讲义，共用 §9 的名词规则）。讨论和运行各一个 skill 而不是合成一个，是 §3.2 的一部分：加载哪个 skill 就是处在哪个阶段。

不改的：§1 全部原则、§5 论坛模型、§11 审核契约、§12 慢环、§16 已否决清单（尤其是：无常驻进程、不打分晋升、AI 不调 close / publish）。

## 3. 运行与契约

### 3.1 运行是一篇 note

一条 line 上可以先后有多次运行。运行是一篇独立的 note（2026-09-17 作者定），理由：它有状态、要签字、要留痕，而且每一步都记在它的跟帖里——**运行 note 的跟帖就是这次探索的轨迹**，feed 里天然可查，不需要另造日志。运行涉及哪些命题 = 各步的帖子里链到的命题，派生，不加字段。

```
kind: run            line: [<线>]
status: discussing ⇄ running → reported        （另有 discussing → dropped，见 §3.4）
signed: <签字那一刻契约的指纹：正文 + steps / max_parallel / until / knobs>
steps: <最多多少步>    max_parallel: <同一时刻最多几步在跑，默认 2>
until: <可选，绝对时刻，如「明早 8 点」>
knobs: {…}           （§8）
正文 = 契约：
  ## 动机        人为什么想做这个（报告第 1 节从这里来）
  ## 方向        每个方向一个 question；人若有猜测，另开一条 conjectured 命题并记下人的 bet
  ## 不在乎      明确不值得花力气的东西（归一化常数、已知结果的复现、边界情形……）
  ## 停止条件    什么算「够写报告了」；什么算「这个方向放弃」
  ## 口味        这位研究者反复说的原话 + 对齐测验的问答
  ## 允许的动作  能否跑脚本、能否联网入库新论文
```

### 3.2 讨论和运行是两个阶段，在 CLI 上分开

不分开会怎样漂：讨论时 agent 顺手就开始推导，没签字的东西混进了轨迹；运行时 agent 悄悄改契约——最典型的是**把「成功」重新定义成它已经找到的东西**；人中途进来说一句「别管那个，去这边」，agent 照做了，契约上写的和实际在做的从此是两回事。三种都让报告分不清哪句是人的意图、哪句是 agent 的推断。

所以阶段就是运行 note 的 `status`，每个阶段有自己的动词、自己的写入面、自己的 skill；不属于这个阶段的动词，CLI 直接拒绝：

| | 讨论中 `discussing` | 运行中 `running` | 已交报告 `reported` |
|---|---|---|---|
| 谁在写 | agent 誊写人说的 | mentor | 人（事后纠正） |
| 写什么 | **契约正文**，可以反复改 | **只有 STEP / RESULT 帖**（§4）；契约正文冻结 | 只有人签名的跟帖 |
| 合法动词 | `run start`、`run sign`（人）、`run stop`（人：作废） | `run step`、`run result`、`run report`、`run amend`（人）、`run stop`（人） | — |
| 被拒绝的 | `run step`——没签字的东西不进轨迹 | 改契约正文——见下 | `run step` / `run result` |
| 授权 | 无。无人在场只做确定性项（v2 §7 原样） | 契约授权要 LLM 的项 | 无 |
| skill | `discuss` | `mentor` | — |

- **签字即冻结。** `magi run sign` 把契约正文的指纹写进 `signed:` 和签字帖。此后正文一动，指纹就对不上：`run step` 拒绝，`next` 与 `sync --close` 报「契约在签字后被改过」。agent 没有任何办法不留痕地改目标。
- **修订是唯一的改法，而且是人的动作。** `magi run amend <运行>`：运行退回 `discussing`，新的步不再登记（已登记的步可以照常 `run result` 结清——那是已经授权过的活）；改完，人再 `run sign`，新的签字帖里带上改了哪几节。mentor 自己觉得契约有问题（某个方向提法不对）→ **不改**，发一条帖说明，转去别的方向，留给人。
- **人中途说的话分两种。** 改变了契约写的东西（方向、不在乎、停止条件、口味）→ 走修订；没改变（「继续」、回答一个停放的押注）→ 一条 `--host human` 的跟帖，阶段不变。判据一句话：**它让契约上的哪一行不再为真了吗？** 这样报告第 6 节能把「人的决定」（签字帖、修订）和「mentor 的决定」（STEP 帖）分开写；§10 里「人中途才有的新意图」那一类也从此有了记录，慢环数得出它发生了几次。
- **阶段是每个入口的第一行。** `magi next`、`magi run status`、SessionStart 钩子的输出，第一行永远是阶段：`讨论中 · 运行〈名〉· 未签字——这里没有任何东西被授权运行` / `运行中 · 第 7/40 步 · 1 步未结清——你是 mentor，契约已冻结` / `已交报告`。任何宿主上的任何 agent，进门第一眼知道自己在哪个模式。
- **讨论阶段不禁止正常工作。** 没有在跑的运行时，项目就是 v2 的日常用法；讨论中读库、入库种子论文、编译、`ask` 都照常——那是知识层的活。讨论阶段写进运行 note 的只有契约；方向（question）和人押了注的猜想（conjectured 命题）是它仅有的热层产物。

### 3.3 契约里的几条

- `discussing → running`（签字）与 `running → discussing`（修订）**只有人能翻**，与 close / publish 同属仪式性动作。
- **预算按步数，不按时长。** 第一稿用「时长 + 续跑次数」，但额度用完、换宿主之间可能隔几小时，挂钟时长在这中间白白流走；步数与哪个宿主、隔了多久无关。`until` 是人真正想说的那种时限（「跑到明早」），可选。
- **并行上限 `max_parallel`**（2026-09-17 作者定：分叉同时走两条可以，但同一时刻的并行数必须有上限，否则额度一下烧完）。默认 2；`steps` 没有默认值，签约时必须填。它由 CLI 在登记步时执行（§4），不靠 agent 自觉。
- **步的粒度交给 mentor**（2026-09-17 作者定：相信 mentor 的判断，契约里不给刻度）。一次推导、一次文献核查、一份讲义各算一步，由它掌握。
- discuss 收尾做一次**对齐测验**：出 3–5 个假想分叉请人回答，问题专挑风险姿态（「只得到已知结果的新表述，继续还是放弃？」「worker 排第一的稳妥选项 vs 排最后的激进选项，选哪个？」）。问答誊进「口味」一节。依据见 §10：偏差集中在这里。
- 人随时可停：`magi run stop <运行>`，或在对话里说停。

### 3.4 实现 A1 时定下的（2026-09-17，与上文不同之处及原因）

- **预算写在签字上，不写在开头。** `magi run sign <运行> --steps N [--max-parallel K] [--until T]`：`steps` 是「签约时必须说的那个数」，那它就该是签字动词的参数；修订后重签不给就沿用。好处是不需要一个「改契约字段」的动词。
- **指纹盖住预算。** 只盖正文的话，不许碰目标的 agent 可以转而把自己的步数改大——`steps: 2 → 200` 同样是改契约。`signed` 不在指纹里；行尾空白和换行风格不算改动（`lint --fix` 会动它们）。
- **多一个终态 `dropped`。** 谈过、没签、不要了的运行，没有出口的话会让 `magi next` 第一行永远写着「讨论中」。`run stop` 在讨论阶段 = 作废。
- **多一个动词 `run report <运行> <drafts/runs/…>`。** 总得有一步把运行翻成 `reported`，而它有自己的检查（报告文件存在、在 `drafts/runs/` 下、**没有未结清的步**——交报告盖过在飞的活，等于把「当时正在做什么」藏掉），所以不走通用的 `thread status`。
- **`--closing` 的步。** 预算用完（或被叫停、过了 `until`）之后还欠一样东西：报告。`run step --closing` 只在预算已尽时合法、不计入步数、最多三个（写、整稿复核、改）——没有上限的话它就是换了名字的第二份预算。
- **通往运行的两扇通用的门关上了。** `run` 一进 `vocab.KINDS`，`thread new --kind run` 和 `thread status <运行> running` 就自动合法了——后者是一个没人签过字、没有指纹、却已经「运行中」的运行。两处都显式拒绝，各有测试。
- **读、判、写在一把锁里**（`threads.transact`）。步号 = 已有步数 + 1、能不能登记 = 对之前帖子的计数；分开做的话两个同时登记的 agent 都是「第 7 步」、都是「两个名额里的第二个」。测试：`max_parallel=1` 下六个线程同时登记，恰好一个成功。
- **Stop 钩子只在运行有进展时拦。** 它记下上次开口时的（步数，已结清数），再次被触发而两个数都没变 → 放行。连着两次停下、中间什么都没登记没结清的 agent，要么卡住了要么做完了，说第三遍也没用；而一个永远拒绝的 stop 钩子就是死循环（v2 §6 的同一条教训）。契约指纹对不上时也不拦——那不是 agent 能解决的事。
- **「权限模式警告」降级成一句提醒。** 原文说签字前由 CLI *检查*宿主的权限模式；各宿主的权限配置各不相同且在变，读它们等于给每个宿主写一段会过期的代码（v2 §9：宿主是数据不是代码）。A1 在签字成功时打印一句提醒，不做探测。
- **契约的节名是固定的英文**（Motivation / Directions / Not worth it / Stop when / Taste / Allowed），因为 `run status` 要按节读回来；节里写什么语言随人。模板的说明文字放在 HTML 注释里，所以没填的节看得出没填，说明文字也不会被当成人的话签进去。有空节时 `run sign` 拒绝，`--anyway` 才签。
- **图谱里运行是 `other` 类**：不给颜色、不进图例。运行是过程记账不是知识；它的帖子里链到的命题照常成边。

### 3.5 A1 的验收：真实的跨宿主冷接手（2026-09-17，通过）

一个一次性的项目，契约是三个算术小问题（6 步、同一时刻 1 步），每个宿主收到的全部输入都是两个字：「继续」。

1. **Claude Code**（`claude -p`，sonnet，限 16 轮以模拟额度用完）：读出自己是 mentor，登记第 1 步（签名 `claude`），写了 `tools/sum_odds.py`、开了命题，在结清之前被轮数上限切断。留下的正是「一个没结清的步 + 一批已落盘的文件」。
2. **Codex**（`codex exec`）：起来了，第一句话就撞上它账号的用量上限，什么都没做。不是安排的，但正是这个功能要应对的那件事。
3. **Antigravity**（`agy -p`，gemini-3.8-flash-high，**没有 Stop 钩子**的宿主）：找到 Claude 留下的第 1 步，**复核了 Claude 的脚本而不是重写**，结清第 1 步，登记并结清第 2、3 步，写报告，`magi run report` 收尾。轨迹上每一帖的签名如实是 `claude` / `antigravity`，签字帖是 `human · via claude`。

所以 §4 的要求成立：状态够不够一个冷的、别家的 agent 接手，答案是够——而且在一个只靠托管块那一句话和 `magi next` 第一行、没有钩子兜底的宿主上也够。

冒烟里学到的、与 MAGI 无关但无人值守前必须知道的宿主脾气（也是「权限模式检查」降级成一句提醒的原因——它们各不相同而且在变）：
- `codex exec` 0.153 已没有 `--full-auto`；要 `--sandbox workspace-write`，不在受信任目录时还要 `--skip-git-repo-check`。
- `agy -p` **不把当前目录当工作区**，默认在它自己的 scratch 目录里干活；要 `--add-dir <项目>`，否则它根本看不见项目，只会反问「继续什么」。
- `magi` 在 PATH 上必须是带 `run` 的版本：钩子和 skill 里敲的都是裸的 `magi`。

一处如实记下的弱点：玩具任务上没有真的分叉，agent 把 `--if-true / --if-false` 填成了「方向 B 解决了 / 没解决」。CLI 只能要求这两栏非空，填得有没有内容是 prose 纪律——要到真实课题上才看得出它起不起作用。

### 3.6 实现 A2–A4 时定下的（2026-09-17，与上文不同之处及原因）

**A2 前提与报告**

- **`premises:` 写入时就校验**（同 `evidence:`）：`thread new --premise`、`thread post --premise`，目标必须是已存在的命题、不能是自己。事后补的前提记成一条字段变更帖。循环依赖不报错，但循环里的命题都**不算立住**——互相撑着的两条主张脚下什么都没有。
- **「立住了」不看便宜档。** 2026-09-03 实测便宜档 12 次判决放过了全部 4 处真错误，所以它的 `stands` 不让命题立住；没写档位的旧帖子照 `weakly_reviewed` 的口径按字面算。
- **向复核方认输不再是人的专属动作。** v2 把「离开 `disputed`」一律归人，理由是不许机器推翻自己的复核方；而 `disputed → refuted` 是作者**同意**复核方，谁也没被推翻。不放开这一条，无人值守的运行会把作者自己都已经放弃的命题一条条停放给人（§7 表格第一行就做不到）。`disputed → supported` 仍然只有人能做。
- **空结果形态在文件里叫 `form: empty`，不叫 `null`**：YAML 把 `form: null` 读成「没有值」，于是一页的空报告被当成完整草稿去检查。命令行是 `magi run outline <运行> --empty`。
- **检查放在交付那一刻（`magi run report`），没有放进 `magi lint`。** 原文写「进 lint」；但这些规则只对一种文件、在一个时刻有意义，放在那个时刻的那个动词上，才是 v2 §1.4 说的「检查要写在会出错的那一层」。查五样：节齐全；没有留着没写的模板注释（没写的节读起来和写了的一样）；不裸引 slug——文中引了某条命题，它的陈述原文必须在文中；名词表每项解析得到概念卡；完整草稿被整稿读过且结论不是 `refuted / unclear`。`--anyway` 可以硬交，交付帖逐条写明哪几项没过。交付前先查有没有未结清的步——这条比文档写得好不好更根本。
- **整稿复核的结论发在运行 note 上，不动任何状态。** 报告不成立该怎么办，是 mentor 的下一步；交付被这条帖子卡住，而不是被某个状态卡住。读稿的一方按「运行里出现最多的那个宿主」回避作者。
- **给人的那一项靠人的一句话清掉**：运行 `reported` 之后，到出现第一条人签名的跟帖（`magi decide --about <运行>`）之前，决策队列里有一项 `report`，写明报告路径和阅读成本。不另设「已读」状态。
- **§7 表格里「不在依赖链上的异议不推给人」只落实了一半**：报告第 9 节只列依赖链上的异议；运行结束后的 `magi next` 仍按 v2 列出全部 `disputed`。要不要在运行之外也按「在不在某条链上」筛，等真用起来再定——那是改 v2 的日常行为，不只是运行的事。
- **运行里开出的命题不问押注**的判定：运行 note 的帖子里链到过的命题。

**A3 讲义与「你会什么」**

- **账本有了 CLI**：`magi familiar list | known | notes | forget`。原文只写了 WebUI 上两个按钮；但作者的另一条要求是「状态在 CLI 里」，而且人在对话里说一句「这个我会」时，agent 得有地方替他按。看板研究地图页上的「运行」卡片显示阶段行（与 `magi next` 第一行逐字相同）和每个方法的两个按钮，写的是同一份账本。
- **「要讲义」在 `magi next` 里是一个 agent 项**（`lecture`），运行内外都提供：人按这个按钮，本来就是为了趁运行还在跑的时候读。

**A4 模式与事后纠正**

- **模式 = `--mode deep|balanced|explore`，展开成旋钮存进运行 note**，`--knob 名=值` 单独改；旋钮算进契约指纹；`magi run status` 把它们渲染成 mentor 照着做的句子。不认识的旋钮原样显示——人也许有自己的意思。
- **`magi run overturn <运行> <步号> --text …`**（人签名）：原文说人读完后说「这里该走另一条」由 agent 誊成跟帖；给它一个动词，是为了让它落在**具体哪一步**上、并且能被慢环机械地数出来。reflect 多了两种 loss 信号：`overturn`（某一步被人事后推翻）和 `amendment`（人中途改契约）——后者正是回放里 5 次漏 5 次的「人中途才有的新意图」，现在至少数得出它发生了几次。
- **账本不能从旁路写**（做 A4 时发现）：`magi thread post <运行> --text "STEP 9: …"` 本来能往运行 note 上写一条没过任何闸门的步；一条 agent 发的、正文以 `SIGNED` 开头的帖子能把人叫停的运行重新放开。现在 `thread post` 拒绝以账本关键词开头的帖子（换个说法照常可以评论），`SIGNED / STOP / OVERTURN` 只认人签名的。

### 3.7 整套走一遍：真实宿主的端到端（2026-09-17，通过）

一个一次性的项目，一条种子笔记（三条一条建在一条上的算术事实）。宿主只有 Claude Code（opus）和 Antigravity；Codex 当天额度用完，每次被点到都失败并回退——复核的宿主回退因此也真跑了十次。

1. **讨论。** 把人会说的话一次说完（方向、不值得做的、停止条件、允许的动作、口味，并声明「马上离开」），要求只写契约。`claude -p`（opus）按 `discuss` 技能：开运行、三个方向各开一个 question、六节写满且**逐句引人的原话**、对齐测验如实写「没有逐题提问」并照录人的那一句、注明「不要替本人填 bet」；没签字、没写脚本、没开命题。
2. **签字。** 人：`magi run sign … --steps 10 --max-parallel 1 --mode deep`。
3. **运行。** `claude -p`（opus）只收到「继续」：4 步做完（预算 10）。命题之间记了 `premises:`；概念卡两张、`depends_on:` 指向它们；分叉处按契约里人的口味两枝都做，多出一条更强的命题（奇数写成平方差的方式数），C 成了它的推论；每条命题翻 `supported` 后自己跑 `magi review`（Codex 失败 → Antigravity 强档，四条都 `stands`，全部标为**立住**）；`run outline --write` → `brief` 写散文 → `magi review <报告>` 整稿 `stands` → `magi run report` 过闸交付。报告如实写着「没有做文献核对：契约把文献调研列为不值得做……不声称任何一条是新的」「没有暴力」。
4. **人的那一侧。** 队列里一项：哪篇报告、「2 个名词对你是新的，0 个有讲义」。按两个按钮（一个「我会」、一个「给我写讲义」）。
5. **换宿主。** `agy -p`（无 Stop 钩子）只收到「继续」：从 `magi next` 接到讲义那一项，写出 `drafts/lectures/telescoping-sum.md`——锚定在命题用它的那一处，并且按账本写着「读者已知平方差恒等式」。队列那一项随即变成「1 个新名词，1 个有讲义」。
6. **事后。** `magi run overturn … 3`、`magi decide --about …` → 队列清空；reflect 读到 4 条 `clean` 和 1 条 `overturn`。看板总览页的「无人值守运行」卡片截图确认。
7. **阶段分割。** 另开一次运行，留一个在飞的步，人 `run amend`（「方向 A 改成 mod 24，等我回来改契约再签」）。`agy -p` 只收到「继续」：把在飞的步标成 `abandoned` 并写明因为契约改了；**没有登记新步、没有写文件、没有碰契约。**

真跑查出、当场修掉并补了测试的：
- 交付后那一项的阅读成本是交付那一刻冻结的——人按了「我会」之后它还说 2 个新名词。现在每次现算。
- 修订后的运行，第一行写着「未签字」，像什么都没发生过；在飞的步也不提。现在写明「本人把已签的契约拿了回去：〈他的话〉」，在飞的步排第一。
- `form: null` 被 YAML 读成「没有值」（§3.6）。

与 MAGI 无关、但值得记一笔的宿主脾气：`agy -p` 在第 7 步里 90 秒就把事做完了，然后进程挂住，超过它自己的 `--print-timeout 900s` 半小时也不退，只能杀。`magi review` 走的是带超时、关 job 即全杀的容器，不受影响；人手工起的 `agy -p` 会。

## 4. 状态在 CLI 里，不在 agent 里

这是第二稿的中心。要求：**一家额度用完，换一家打开同一个目录，说一句「继续」就能接上，不重做已经做完的，也不丢正在做的。**

**mentor 是座位。** 谁在这个目录里跑 `magi next` 且有一个 `running` 的运行，谁就坐在 mentor 的位置上。它的工作记忆只有一份：运行 note。和人做 discuss 的那个会话不再特殊——它带着的默契，凡是值钱的，都必须在签字前写进契约（「口味」「不在乎」「停止条件」）。§10 的回放支持这样做的代价很小：能迁移的那部分对齐正是写得下来的那部分（给原话就转了风险姿态），而写不下来的那部分（人中途才有的新意图）给全部动机文档也补不上。

**步是唯一的写入口。**

```
magi run step <运行> --do "做什么" --because "为什么"
                     --if-true "成立则……" --if-false "不成立则……" [--on <命题或方向>]
      → 追加一条 STEP 帖，返回步号。拒绝：运行不是 running / 契约指纹对不上 /
        步数用完 / 过了 until / 未结清的步已达 max_parallel
magi run result <运行> <步号> --text "一小段结论" [--abandoned]
      → 追加一条 RESULT 帖，结清这一步；正文链到产出的命题、草稿、脚本
magi run status <运行>
      → 接手简报：契约摘要、旋钮、剩余步数、未结清的步、最近 5 步及其结果、
        停放的要人项的数量、自某步登记以来改动过的文件
```

由此派生，全部不另存（v2 §1.3）：

| 要的东西 | 怎么来 |
|---|---|
| 预算 | 已登记的 STEP 帖数 vs `steps` |
| 并行上限 | 没有对应 RESULT 的 STEP 数 vs `max_parallel` |
| 「上一个会话死的时候正在做什么」 | 没有 RESULT 的 STEP。接手后 `next` 第一条就是它：重派，或 `--abandoned` |
| 轨迹、报告的「决断」一节 | STEP 帖本身（做什么 / 为什么 / 成立则 / 不成立则）+ RESULT |
| 琐碎检验 | `--if-true` 与 `--if-false` 都不改变下一步 → 这一步不该登记 |

三条配套纪律（写进 `mentor` skill 与托管块）：

1. **边做边存。** worker 的中间产物先落文件（`drafts/`、`tools/`、命题跟帖），再继续；额度在半途用完时，留下的是一个未结清的步加一批已存在的文件，而不是一段消失的上下文。
2. **不用宿主私有的状态。** 宿主的 todo 列表、plan 文件、自带记忆对另一家不可见（v2 §9：宿主 auto-memory 视为私有缓存）。要紧的东西只走 `run step / result` 和 `thread post`。
3. **回给 mentor 的那一小段话也要落帖。** 第一稿里它只存在于 mentor 的上下文——那正是换宿主时丢掉的东西。`run result --text` 就是它的家。

并行上限管的是**登记的步**。agent 不登记就偷偷多派，CLI 拦不住——与 MAGI 其余记账同一信任层级；Claude Code 上已有的子 agent 计数钩子可以顺带报出「派出数 > 未结清步数」，只报不拦。

## 5. 驱动：让它不停下来

预算和并行的闸门已经在 CLI 写入口上，对每个宿主都成立。**驱动只管一件事：别在还有预算时停下。** 它是便利，不是闸门：

- 有 Stop 钩子的宿主（Claude Code、Codex）：今天的钩子已经在跑 `sync --close`、用 `{"decision":"block"}` 拦未记账的停机。加一条——有 `running` 的运行且还有步数 → 拦住，理由 = `magi run status` 的头几行。
- 其他宿主：托管块里一句话（「有运行在跑就继续，直到 `magi run status` 说停」），尽力而为——与 `sync --close` 今天的不对称相同。
- 步数用完而报告未写 → `next` 只剩一项：写报告（它本身也是一步，所以写到一半断掉同样能接手）。
- 额度用完属于异常终止：没有 Stop 事件，运行停在 `running`。**换任何一家宿主进来，SessionStart 钩子 / `magi next` 的第一条就是接手简报。**
- 签字前 CLI 检查一件事并警告：宿主当前的权限模式会不会在无人时弹窗把运行卡死。

v2 已否决常驻进程，这里也不需要。**本版不做** MAGI 自己循环起无头 agent 的驱动：它要给无头 agent 跑脚本的权限，先让 2026-09-17 刚加的进程容器（`core/proc.run_contained`）在复核上用一阵再说。步的记账与驱动无关，换驱动不改契约。

## 6. 角色与前提

**mentor** ——只读地图层：运行 note、line note、question、各命题的 claim 与状态。规则：

1. 不做复核。宿主有子 agent 时不做推导，派给 worker；没有子 agent 的宿主上自己做，但照样先 `run step`、后 `run result`。
2. **每一步先登记再动手**（§4）。
3. **便宜的分叉不单选**：worker 给出选项时，同时走它最看好的和最激进的（旋钮 `fork_width`，受 `max_parallel` 约束）。依据见 §10：mentor 会顺从 worker 的排序，而人经常选最激进的那个。
4. **永不替人押注、永不签字、永不 close / publish。** 人没表态的 bet 就是 unknown。
5. 每关掉一个命题、或每 N 步，退到 story 层讲一遍（图像是什么、核心 insight 是什么、暴力搜索也照实说），对照契约的目标和不在乎清单，结论写进一条 RESULT。依据见 §10：这类纠偏 mentor 做得最好。
6. 要人的项一律停放，转去别的方向——多个方向的意义就是运行永远不被卡住。

**worker** ——照现有 `research` / `compile` / `ingest` skill 干活，用 `thread new / post / status` 记账。模型按活选，不默认继承 mentor 的。

**reviewer** ——`magi review` 原样不动：无头、跨厂商、强档、跑在进程容器里。变化只在**谁来跑**：v2 是「列出、不自动跑」，运行内由 mentor 在 `next` 列出时执行（契约授权）。换了宿主，命题作者的签名跟着变，「挑一家不是作者的」照常成立。

**前提**：`premises: [[命题]]`。派生出一个词——命题**立住了** = 自己被强档复核判 `stands`，且所有前提都立住了。

- `next` 在运行内的排序：先复核将要被当作前提的命题，再在它上面往下做。
- 前提后来被 `refuted` → 下游命题进记账债（「前提倒了，重看」）。不自动翻状态——v2 §4：跃迁表抓记账错误，不管科研怎么做。
- 没有 `answers:` 也不是任何命题前提的命题，运行内的 `next` 不提供。琐碎但必要的引理，等目标链上真用到时再开。

## 7. 什么能到人面前

运行期间：**零**。运行结束：决策队列里**一项**——「运行 X 已交报告：〈标题〉，新名词 N 个、其中 M 个有讲义」。人看这一行决定什么时候花整块时间。

| 停放的项 | 到人面前？ |
|---|---|
| disputed，作者 agent 同意驳回 | 否。直接 `refuted`，继续 |
| disputed，僵持，命题在某篇报告的依赖链上 | **是**，列在报告末尾 |
| disputed，僵持，不在任何依赖链上 | 否。留在 MAP 队列，不推 |
| 「只被便宜档复核过」「证据在库外」「复核方答的时候还有进程在跑」等 | 只有在依赖链上才列 |
| radar 分诊、reflect 提案 | 与运行无关，照 v2 |

## 8. 旋钮与模式

模式不是代码路径，是契约里一组旋钮的名字。除 `review`、`steps`、`max_parallel` 外，旋钮都是**渲染进 `magi run status` / `next` 输出的指令参数**，不进 `candidates()` 的排序代码——硬菜单软选择不变，只是选的人从「人 + 对话」换成 mentor。旋钮写在 note 里，所以换宿主后照样生效。

| 旋钮 | 深挖 | 平衡 | 探索 |
|---|---|---|---|
| `open_questions` 能否自己开新方向 | 否 | 限量 | 是 |
| `order` 先做哪个 | 最有希望那条线的最深处 | 混合 | 访问最少的方向 |
| `abandon_after` 连续几次受挫就放弃方向 | 高 | 中 | 低 |
| `fork_width` 分叉处同时走几条 | 2 | 2 | 1 |
| `review` | 每次翻 supported 都审 | 同左 | 只审要当前提的 |

不对称写明：**探索模式的产物是猜想地图**（命题停在 `conjectured`，不宣称 supported）；**深挖模式的产物是一条立住的链**。

## 9. 运行报告、讲义、名词规则

**报告**（`brief` skill 写，输入只有文件：依赖链 + 运行 note——所以哪家宿主都能写，写到一半断了也能接）。节固定；第 2、3、4、8 节直接来自作者在以往会话里反复问的那几个问题（§10 的普查）：

```
摘要（五行）+ 阅读成本
1 动机                     ← 契约
2 证明了什么 / 没证明什么     每条标「立住 / 未审 / 有异议」
3 哪些是新的，哪些文献已有    ← 一次新颖性核查（radar / citation-gap 现成机制）
4 物理图像与核心 insight     暴力搜索照实说（命题结案的 key_move 已有这个词表）
5 推导                     依赖链顺序；只留「做了决断的」和「不显然的」，常规步骤进附录
6 决断                     每个分叉选了什么、放弃了什么 ← STEP 帖的「成立则…不成立则…」
7 有价值的失败              ≤ 5 条，每条三行：试了什么 / 败在哪一步或反例 / 它排除了什么
8 这个方向还 promising 吗，下一步
9 预备知识（讲义链接）+ 名词表 + 仍需你裁决的异议
```

- 第 7 节只收**过了复核的驳回**，且二选一：人押过注的方向上的失败；或依赖链某个分叉处被放弃的那条路。「agent 卡住了」不收。
- **空结果形态** = 只有 2、6、7、8，一页；**不走整稿复核**（2026-09-17 作者定：它不宣称任何东西立住了）。大多数运行会是这个结局，所以它必须短。
- 草稿形态交付前**整稿复核**：`magi review <报告路径>`，同一套无头跨厂商机制、另一份提示词——查链条是否衔接（命题被 restate 后下游用的还是不是同一句话）、记号是否统一、有没有用了却没定义的词。逐命题复核看不到这些，而统一记号这一步本身会引入错误。
- 人读完后说「这里该走另一条」→ agent 以 `--host human` 誊成运行 note 上的跟帖。它是 reflect 的一种新 loss 信号（分叉选择被人推翻），慢环据此提议改契约模板。

**名词规则**（适用于一切给人读的文字：报告、通知、MAP）：

1. agent 不许自己起名；新名字先登记成概念卡才能出现。
2. slug 不单独出现，必须带着 claim。
3. 不在熟悉度账本里标「会」的词，首次出现时给定义或链到讲义。
4. 通知里写阅读成本。

能写成门的写成门（v2 §1.4）：报告必须有名词表且每项解析得到概念卡、正文里的裸 slug，进 `lint`；「用了却没定义的词」交给整稿复核——这条机器查不了。

**方法清单**：运行涉及的命题的 `depends_on:` 并集。不另外打标签——2026-09-08 实测自由打标 10 个数学块出了 47 个名字，而概念卡就是规范名，别名合并是 `tidy` 已有的活。

**熟悉度账本**：`~/.config/magi/familiar.jsonl`（2026-09-17 作者定：用户级，人会什么跟人走，不跟项目走）。不给人建模，直接问：WebUI / MAP 列出方法清单，每项两个按钮——「给我写讲义」/「我会」。这是运行期间人唯一**可以**做的事，而且可以不做。查不到的词按「不会」处理（多给一句定义的代价小于少给）。

**讲义**：独立的一步（登记、结清，与别的步一样），`drafts/lectures/<概念>.md`，带引用。输入：概念卡 + **worker 实际用它的那一处推导** + 熟悉度账本 + 库里的原始文献。讲义锚定在使用处（「命题 P3 里是这样用的」），所以它就是报告的预习材料。

## 10. 依据：2026-09-17 的普查与回放

**普查**：四个物理课题的探索会话，约 117 条人的输入，手工分类——反复重申的价值观 ~28%、要全局图景 ~26%、单纯「继续」~20%、押注 ~9%、在 worker 给的选项里选 ~8%。两个结论：纠偏大多是同一套价值观的重申 → 可以一次写进契约；「要全局图景」的那几个问题 → 就是报告的节。另：这些会话里出现过三次「额度用完了 / 不要并行派 subagent / 串行慢慢跑」——`max_parallel` 和 §4 不是假想的需求。

**回放**：26 个时刻（15 个纠偏、11 个「继续」），Fable 当 mentor，只给该时刻之前的内容。

| | 裸 mentor | + 其他课题里的原话 |
|---|---|---|
| 「继续」11 处判对 | 8 | 9 |
| 纠偏 15 处（对一半计 0.5） | 6.5 | 7 |

按类型：**从细节里拉出来 / 先粗后细 / 讲 story**——5 处判对 4–5 处，这是最常见的一类；**收敛还是冲锋**——裸 mentor 偏保守，给了原话 3 处翻过来 2 处，「直接试最激进的那个」三组全错；**人中途才有的新意图**——5 处全漏，再给项目动机文档也是 0。后者是天花板：事前对齐补不了事后才形成的意图，只能靠报告第 6 节让人事后纠正，代价是在次优分支上多跑一段。

这组数字同时是 §4 的依据：回放里的 mentor 本来就是**冷的**——一个没参与过任何讨论的新会话，只读到了写下来的东西。它的表现就是「换一家接手」的表现。

局限：样本小、每组一次、由设计者本人按内容评判且知道组别；mentor 只看到汇报的最后 7000 字；人当时的选择也不等于正确答案。

## 11. 本版不做

- MAGI 自己循环起无头 agent 的驱动（§5）。
- follow 阶段的 coach（读报告时每个分叉先猜再看）：方向是对的——它不再和 3–12 秒的窗口抢时间——但静态文档承载不了，等 WebUI 有报告阅读面再说。
- 给人的知识储备建模。只问、只记。
- 用回放去学 `next` 的排序或 mentor 的选择：没有分数，样本太小。
- agent 自评「这是大发现」。通知只带事实（标题、摘要、立住的比例、新颖性核查结果、阅读成本），算不算大发现由人判。
